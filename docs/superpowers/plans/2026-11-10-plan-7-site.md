**Goal:** Finish Apollo for recruiters and for Vaughn:
- the Backtest, Models and Case study pages;
- the guided tour and the three explainers;
- a nightly public snapshot on GitHub Pages that never publishes the private journal;
- the README and model cards.

Along the way it fixes two everyday problems from Plan 6: only MNQ has local data, and the first forecast of the day takes about 2 minutes.

**Architecture:**
- **Python:**
  - `apollo.data.sync` copies the `data` branch's bars, context, quality and ledger into the local `data_store/`, leaving `journal.duckdb` alone.
  - The forecast is cached on disk once per New York day.
  - The backtest report gains per-trade rows, daily equity curves and a monthly table.
  - The models report gains feature importance and the live ledger summary.
  - `apollo.export.snapshot` writes everything the site reads as JSON files.
- **Web:**
  - `VITE_MODE=static` swaps the API client for a reader of those JSON files and makes the app read-only.
  - The new pages are hash routes, like Plan 6's.
  - Charts are hand-drawn SVG plus the existing `lightweight-charts`, so no chart library is added.
- **Publishing:** `.github/workflows/publish.yml` runs after the nightly collector. It exports the snapshot, builds the static site and deploys it with GitHub's own Pages actions.

**Tech Stack:** no new Python or npm packages. GitHub Actions `actions/configure-pages@v5`, `actions/upload-pages-artifact@v3` and `actions/deploy-pages@v4` are GitHub's own and free for public repos. `ffmpeg` (already on Vaughn's Mac) turns a Playwright recording into the README GIF once, by hand. It isn't a project dependency.

## Global Constraints

- **Privacy (spec 5.10):** the private DuckDB journal never leaves the laptop. The snapshot holds only `source = "imported"` journal rows. Those are the case study's already-public, scaled data. Notes, screenshots, `model_snapshot` and anything from `manual` or `signal` rows are never exported. Snapshot files go to `web/public/snapshot/`, which is git-ignored.
- **Honesty line** on every page: "Research tool. Not financial advice." Backtest numbers are labelled "development" unless they come from a `--final` run. Case-study dollars are labelled "scaled".
- **The holdout stays locked:** nothing in this plan runs `--final`. The nightly job runs development backtests only.
- **Static base path:** GitHub Pages serves the repo at `https://vaughnantonio.github.io/Apollo/`. The static build sets Vite `base: '/Apollo/'`, and every snapshot URL is built from `import.meta.env.BASE_URL`.
- **Design:** the Plan 6 tokens and taste rules apply. Charts follow the `dataviz` skill: one accent (`--brand`), `--down` for losses only, direct labels rather than legends where they fit, and Geist Mono for numbers. Every chart has a text alternative: a table or an `aria-label` summary.
- **Motion:** every new animation sits inside `prefers-reduced-motion: no-preference`, including the Plan 6 leftovers in Task 12.
- **Prose** (page copy, the README, model cards, comments) uses the humanizer skill. Investor skills stay out of the signal and the backtest (spec 5.15).
- **No new dependencies.** Ask Vaughn before adding any.

## Review Focus

1. **The snapshot leaks private data.** With manual and signal rows in the journal (notes, screenshots, snapshots), the exported files contain none of them, and no file mentions `journal_media`. *Test: Task 4.*
2. **The site is served under `/Apollo/`.** Snapshot fetches and assets resolve under the base path, not the domain root, and a deep link such as `/Apollo/#/models` loads. *Tests: Task 5 (URL building) and Task 11 (the built `index.html` references `/Apollo/assets/`).*
3. **A symbol has no backtest, models report or bars,** such as MES with no backtest file or NVDA with no model. Each page shows an empty state for that symbol rather than crashing, both live (404 from the API) and static (missing file). *Tests: Tasks 6, 7 and 8.*
4. **The nightly job fails partway**, for example when Yahoo is down or one symbol's refit raises. The exporter writes what it can, lists what's missing in `meta.json`, and the deploy still runs. A failed build leaves the previous site up. *Tests: Task 4 (one failing symbol) and Task 11 (`continue-on-error` only on per-symbol steps).*
5. **The tour meets a target that isn't on screen**, such as the rail below the chart on a phone, or a step whose element is missing. The step scrolls its target into view and skips a missing target, and Escape ends the tour. Once dismissed, the tour never comes back, and if storage is blocked it isn't offered at all. *Test: Task 9.*

### Task 2: Forecast cache, feature importance, ledger summary, /models

**Files:**
- Modify: `src/apollo/models/report.py`, `src/apollo/api/main.py`
- Test: `tests/models/test_report_extras.py`, `tests/api/test_api.py`

**Interfaces:**
- Produces:
  - `forecast_cached(root: Path, code: str, today: date, cache_dir: Path = Path("reports")) -> dict`.
    - It reads `cache_dir/forecast_<code>.json` when its `"date"` equals `today` (NY), and otherwise calls `build_report(root, code)` and writes that file.
    - It returns `{"date", "latest", "range", "regime_model", "model_check", "importance", "ledger"}`. Plan 5's `model_check(sessions)` moves here from `api/main.py`.
  - `feature_importance(model, X: np.ndarray, y: list[str], names: list[str], top: int = 10) -> list[dict]` returns `[{"feature": str, "drop": float}]`, sorted by `drop` descending. It uses `sklearn.inspection.permutation_importance(model, X, y, scoring="neg_log_loss", n_repeats=10, random_state=0)`. `build_report` calls it on the chosen model, fitted on every session except the last 60 and scored on those 60, so the importance is out of sample. It's stored as `report["importance"]`.
  - `ledger_summary(root: Path, code: str) -> {"since": str | None, "n": int, "scored": int, "hit_both": float | None}`, read from `root/ledger/<code>/*.json`.
  - `GET /forecast` uses `forecast_cached`.
  - `GET /models?symbol=` returns `reports/models_<code>.json` (the `--ablation` CLI output) plus `ledger_summary`, or 404 "no models report yet; run python -m apollo.models.report --ablation".
